structure Person where
  email : Key String          -- owns email @key
  name  : String              -- owns name @card(1..1)
  age   : Option Int64 := none
  deriving Entity

structure Friendship where
  a : Role "friend" (Ref Person)
  b : Role "friend" (Ref Person)
  since : Std.Time.PlainDate
  deriving Relation
Plain Lean structures become TypeDB entities and relations.
def befriend : Tx .write Unit := do
  let ann ← Entity.insert
    { email := "ann@example.com", name := "Ann" : Person }
  let bob ← Entity.insert
    { email := "bob@example.com", name := "Bob" : Person }
  discard <| Relation.insert
    { a := ann, b := bob,
      since := Std.Time.PlainDate.ofYearMonthDayClip 2021 3 14 : Friendship }

-- commits on success, rolls back on any error
d.runSync "social" .write befriend
A write transaction is its own type, and it commits atomically.
structure FriendOf where
  name : String
  friend : String
  deriving FromRow

def friendsOf (who : String) : Tx .read (Array FriendOf) :=
  query typeql!"match
    $x isa person, has name {who}, has name $name;
    $f isa friendship, links (friend: $x, friend: $y);
    $y has name $friend;"
{who} is escaped, so user input can never change the query.

Why it exists

Two type systems should not meet through strings

TypeDB types your data. Lean types your program. Most clients throw both away at the boundary. typedb-lean keeps them and connects them.

A typical database client

  • Queries are strings glued together at run time
  • User input concatenated into a query can rewrite it
  • Results come back as untyped maps or JSON
  • An insert in a read-only transaction fails in production
  • Decimals and durations pass through floats and lose precision
  • Code and schema drift apart silently

typedb-lean

  • typeql! queries carry the transaction mode they need
  • Every interpolated value is escaped by its type's ToTypeQL
  • Rows decode straight into your structures with deriving FromRow
  • An insert in a Tx .read does not compile
  • Decimal, Duration and Std.Time keep values exact
  • Schema.verify! fails fast at start-up if they differ
Types everywhere

One definition, checked on both sides

A Lean structure is the single source of truth. It generates the schema, decodes rows, and is verified against the live database.

Features

Everything you need, nothing you don't

Small, composable layers over TypeDB's official driver.

Typed transactions

Tx .read, Tx .write and Tx .schema are different types. A query that needs more than its transaction allows does not compile.

How the modes work →

Injection-safe queries

typeql!"… {value} …" renders every value through ToTypeQL. A value with no rendering is a compile error, never a string concatenation.

Typed results

Rows decode into structures with deriving FromRow; fetch documents through FromJson. Stream millions of rows in constant memory.

Decoding →

A lightweight ORM

deriving Entity and deriving Relation: inserts, reads, updates, deletes, subtypes, relations that play roles, polymorphic reads.

The ORM →

Migrations

Versioned up and down steps, with history and checksums kept in the database. One step can change the schema and backfill data atomically.

Migrations →

Async and fast

Driver.run returns a Std.Async computation on its own thread. Batched decoding matches the Rust driver on scans and lookups.

Mistakes become compile errors

The compiler knows what a transaction may do

Every query carries the weakest transaction mode that may run it, read off its text: define needs schema, insert needs write, match needs read. Every operation asks the compiler for evidence that the current mode allows it.

Read helpers lift into write transactions on their own, and you can write helpers that work in any mode strong enough to run them.

Knowledge graphs

Research and domain knowledge

N-ary relations, relations that play roles in other relations, and subtype hierarchies map to Lean structures with Role, Ref and extends. Polymorphic reads decode each instance into its own type.

Finance

Ledgers and balances

An exact Decimal with 19 fractional digits, durations that keep months and days apart, and a retry policy that re-runs a transfer only when its commit loses a conflict.

Policies

Access control and rules

Who may do what, through which role, under which grant. Model it as relations, encode the rules in TypeQL functions, and keep the queries that check them injection-safe.

Get started

Up and running in three steps

You need Lean 4 (via elan), a Rust toolchain, protoc and Docker.

Add the package

The first build compiles TypeDB's C driver; later builds reuse it.

require «typedb-lean» from git
  "https://github.com/Volland/typedb-lean" @ "v0.1.0"

Start TypeDB

The default credentials are admin / password.

docker run -d --name typedb \
  -p 1729:1729 typedb/typedb:3.14.0

Connect and query

Everything returns EIO TypeDBError α.

Driver.withDriver

  d.ensureDatabase "hello"
  d.runSync "hello" .read (query …)

FAQ

Questions

Do I need to know TypeDB already?

No. Chapter 2 of the mini book teaches entities, relations, attributes, roles and TypeQL from scratch, with queries you can run.

Do I need to know Lean already?

Basic functional programming helps. Chapter 3, Just enough Lean, covers structures, type classes, do notation and the bit of dependent typing the library uses.

Which TypeDB versions are supported?

TypeDB 3.x. The library builds the official C driver at a pinned version (currently 3.14.0), and its integration tests run against a typedb/typedb container of that version.

Which platforms?

Linux x86_64, Linux arm64 and macOS arm64, with Lean v4.35.0. Building needs a Rust toolchain and protoc, or a prebuilt driver library via TYPEDB_DRIVER_LIB.

Can I connect to a remote server with TLS?

Yes. Config takes username, password, and tls := .system or .rootCA path.

Is it ready for production?

v0.1.0 is the first release. It has unit tests, compile-time checks and integration tests against a real server in CI on every push, and benchmarks with enforced targets. Try it, and report what you find on GitHub.

How is it licensed?

Apache-2.0.
